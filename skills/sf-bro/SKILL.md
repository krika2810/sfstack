# sf-bro

sf-bro restates the previous message in plain, simple language. Same facts, same IDs, same caveats; fewer words and simpler sentences. It loses jargon, never substance.

## When to use it

- The user says "bro", "what?", "in English", or shows confusion.
- Your last reply was dense and you can feel it.

## The rules

1. **Keep every fact.** IDs, numbers, decisions, caveats all survive. Plain means simpler words, not less truth.
2. **Short sentences.** One thought each.
3. **Explain any unavoidable term in a few words.** "A scratch org (a throwaway copy of your Salesforce setup)".
4. **No new content.** Do not add analysis the original did not have. The job is translation, not expansion.

## Gotchas and failure modes

- **Losing the caveat.** "It is basically done" is not the plain version of "done pending the validation job". Simplify the words, never the facts.
- **Adding content.** New analysis in the restatement makes the user wonder which version to believe. Translate only.

## Proof it worked

A reader who bounced off the original can act on the restatement without asking what anything meant.

## Reply

The restated message only.
