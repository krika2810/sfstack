# Playbook: investigation

A read-only question: how does this automation work, why was it built this way, are we sure.

1. Restate the question in your own words and confirm scope before digging.
2. Run `/sf-how` for mechanics, `/sf-why` for intent. Evidence over reading: describe the schema, map the automations, watch a debug log in a scratch org if the answer is behavioral.
3. Answer with the evidence attached: source references, log excerpts, query results. Distinguish "observed" from "inferred" explicitly.
4. Write nothing, deploy nothing. If the answer demands a change, that is a new task - report the finding.
