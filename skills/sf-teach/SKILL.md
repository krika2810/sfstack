# sf-teach

Run `/sf-how` and `/sf-why`, then weave what they find into one plain explanation. Build it up piece by piece: the data model first (objects and relationships are the nouns), then the automation map (the verbs), then the transaction story (what happens, in what order, when a user does the thing), then the why (the decisions and constraints that shaped it).

Use the platform's own vocabulary and define it on first use - order of execution, governor limits, sharing model - because the listener will meet those terms in every future conversation. No analogies that replace the mechanism; the mechanism, plainly stated, is the explanation. Check understanding by having the explanation survive questions, not by compressing it further.
